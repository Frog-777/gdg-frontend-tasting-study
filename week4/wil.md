## 4주차 스터디 내용 정리 ##

목표
1. 클릭(하트)을 했을 때 할 일을 어떻게 연결하는가
2. 누른 선택은 어떻게 화면에 담기는가
3. 누른 사람에게 어떤 도움을 주는가

*왜 이런 반응이 필요한가를 설명할 수 있도록 함

1. 하트 클릭 후에 변경되어야 하는 내용
(1) 하트 색이 빨간색으로 채워짐
(2) 좋아요 수가 +1 됨

2. 위 내용을 실행시키기 위해서는 함수가 필요함
임시 이름 : handleClick 으로 지정
- onClick={handleClick}
: 이 버튼을 실행하면 handleClick이라는 함수를 실행해달라는 의미를 가짐
- onClick={handleClick} vs onClick={handleClick()}
괄호 없을 때 : 클릭할 때 실행
괄호 있을 때 : 화면을 만들 때 실행(지금 실행)
-> 우리는 클릭할 때 실행되길 원하기 때문에 지금은 괄호가 필요없음
- Console에서 확인 가능

3. React에서 선택을 기억하는 법
- let liked = false;
false : 아직 선택 안 함
true : 좋아요 선택
- 변수값을 바꾸는 것만으로는 클릭 후에 화면이 변하지 않음
-> 지금 필요한 것 : 다음 화면에서도 값을 기억하기, 선택이 달라지면 화면 계산 요청하기
- state(상태) : 화면에 영향을 주는 컴포넌트의 현재 상태
-> React가 상태를 기억하고 바뀐 값으로 화면을 다시 그림
- useState : 상태를 기억하고 바꾸는 함수 (이런 React함수를 Hook이라고 함)
(ex) 좋아요를 선택했는지 기억함
    (1) useState에 첫 상태를 알려줌 '''const [liked, setLiked] = useState(false);'''
                                : false가 초기값이고 이후에는 현재 상태를 받음
    (2) liked : 이번 화면에서 읽는 상태 -> liked는 읽고
    (3) setLiked : 다음 상태를 요청하는 함수 -> setLiked로 변경 요청
    (4) 한 번 더 누르면 취소 됨 '''setLiked(previous => !previous);'''
                            : previous 이전 선택(선택 안함), => 다음 선택 계산(선택함), ! 반대로 바꾸기(선택 안함)
- 정리 : 새 상태로 JSX를 계산한 뒤, 필요한 변화를 화면에 반영함
클릭 handleClick -> 상태 업데이트 요청 -> 새 상태로 화면 계산 -> 필요한 화면 반영
- 1주차 vs 4주차
1주차 : Event, JavaScript, DOM을 직접 변경
4주차 : Event, State 업데이트 상태로 UI 표현
- Props vs State
Props : 부모가 전달하는 정보(부모가 새 값을 줄 수 있음, 자식이 직접 수정하지 않음)
State : 컴포넌트가 관리하는 상태(변경 함수로 요청함, 다시 그릴 때도 이어짐)
- useEffect : 상태와 브라우저 기능을 맞추는 함수
(ex) 재생 상태에 맞춰 실제 영상을 재생/정지함
*버튼 표시와 실제 영상 재생은 다른 영역(구분 필요)
- useState vs useEffect
useState : 상태를 기억함
useEffect : 필요한 기능과 연결함

4. 화면의 반응
- Interaction vs Animation
Interaction : 내가 행동하면 화면이 대답함
Animation : 변화가 움직여 보이도록 표현함
* 움직임이 없어도 화면의 대답은 Interaction
- 반응 비교하기
(1) 하트 그대로 : 눌렸는지 알 수 없음
(2) 좋아요 숫자, 하트 모양 변화 : 선택한 결과가 보임
(3) (2)번 변화 + 큰 하트 표시 반응 : 결과는 알 수 있으나 읽던 곳을 가림
-> (2)가 항상 정답은 아님, 사용자와 맥락이 달라지면 (1) 또는 (3)이 더 좋은 반응일 수 있음
- 기다림의 표시 방법(예시) : 로딩 표시, 스켈레톤 UI(게시글이 들어올 자리를 빛으로 알려줌)        
-> 사용자 경험(UX)을 고려하면서 화면의 반응을 표시해야 함

5. 반응을 설계하는 감각
- 버튼 누른 이유를 생각한 후(버튼 목적 고려)에 표현을 정함
- 움직임을 줄여도 결과는 남아야 함
