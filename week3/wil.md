## 3주차 내용 정리 [Component 나눠 담기] ##
1. 화면 나누기
Q. 하나의 파일에 코드를 전부 담아야 할까?
A. 화면의 구성을 코드에 한 번에 담으면 구조를 이해하기 어렵기 때문에
기능별/영역별로 나누어 코드를 작성하는 것이 좋음(나누는 기준에는 정답이 없음)
> 나누기 위한 질문 예시  Q. 무슨 역할?
                    Q. 반복되는가?
                    Q. 하나의 단위로 볼 수 있는가?
> 잘게 나눈다고 좋은 건 아님
> 나눈 뒤에 역할에 따라 이름을 잘 붙이는 게 매우 중요함

2. Component
: 화면에서 찾은 구조를 코드에서도 표현하는 단위(화면 일부를 하나의 단위로 표현)
- Component 이름은 대문자로 시작한다
비교)    html-<div/> 소문자로 시작
        Component-<Profile/> 대문자로 시작
- 만든 Component는 JSX에서 태그처럼 사용할 수 있음 <Profile/>

3. 실습 과정 정리
(1) 준비된 React 프로젝트 실행
(2) App.jsx에서 Profile 찾기
(3) Profile Component로 나누기
    (2)에서 찾은 Profile 덩어리를 가져와 <Profile>라는 이름으로 새로운 Component 생성
    원래 Profile 덩어리 위치에 <Profile/> 태그하기
    ** 대문자 명심하기 **

4. 같은 구조 다른 값(Props, Data)
같은 구조의 게시글에 다른 값 전달하기
- Props : Component에 값을 전달하는 하나의 방법
- Props의 흐름 : 보내기 -> 받기 -> 보여주기

[구조는 Component로, 달라지는 값은 Props로]

5. 하나 만들고 여러 번 쓰기(Array, map)
(1) Array
: 여러 개의 게시글 -> 여러 개의 데이터(데이터 하나가 Post 하나로)
- React 말고 Javascript에서도 존재하는 문법

(2) map
: 배열의 각각을 새로운 결과로
- JavaScript의 문법 중 하나
- 각각의 데이터를 화면으로(UI로) 표현하는 것

6. 나누는 것도 설계
> 개발은 코드를 치면서 시작되는 것이 아니라 목표를 정하고 구조화하는 것부터 시작되는 것이다. 

3주차 스터디 배운 점 / 느낀 점
지난주까지 스터디하면서 복잡한 화면일수록 코드가 더러워지고 코드를 한 번에 이해하는 게 어려워질 거라고 생각했다. 이걸 해결할 많은 방법 중 오늘 배운 Component가 매우 유용하게 쓰일 것 같다. 
코드를 잘 짠다는 건 나 뿐만 아니라 다른 사람이 코드를 볼 때도 한 번에 이해할 수 있게 만드는 것이라는 걸 오늘로써 더 잘 이해하게 되었다. 그러기 위해서는 다양한 도구를 필요한 곳에 잘 배치하여 이용하는 게 중요한 것 같다. 매 주차마다 배우는 새로운 도구를 반복적으로 적용해보는 연습이 필요할 것 같다. 3주차 스터디도 너무 유용하고 재미있었습니다~!!
